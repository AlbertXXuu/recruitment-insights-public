# 企业工作账号申请与审核

个人求职者在 `/login` 注册；企业申请人在 `/join` 创建独立工作账号，并填写企业名、联系人、联系方式、公开介绍链接（可选）和申请说明。演示时填写合成资料，例如 `review@example.test`，不需要真实企业证件。

1. 提交成功后登录该工作账号，查看申请状态。审核前只有普通权限，不能维护企业岗位或授权成员。
2. 管理员登录后进入“企业入驻审核”（`/enterprise-review`），查看详情，填写原因驳回，或通过申请。
3. 被驳回或撤回的申请可以修改重提；每次操作保存历史。已通过申请不能再次更改企业归属。
4. 通过后原工作账号成为企业负责人，刷新后进入企业端；负责人在“成员授权”中创建 HR，并决定是否允许维护岗位。
5. HR 撤权在后续请求中生效；只读 HR 可以查看本企业岗位，但不能写入或自行授权。其他企业不能读取私有岗位或维护本企业数据。

个人注册固定普通身份；申请接口也不接受客户端指定角色、企业 ID 或管理权。企业名使用 Unicode 规范化、去空白和大小写折叠检查明显同名变体，不能凭相同企业名加入已有企业；加入已有企业由其负责人创建 HR。

审批、企业创建、身份变更、历史和审计在同一事务提交，过期版本和重复审批被拒绝。工作账号已有个人简历或收藏时不能批准为负责人，应驳回并要求使用独立工作账号。已有个人账号不能由申请接口自动转为企业账号。

这是本地演示与课程测试流程，没有邮件验证码、营业执照核验或真实企业认证，也不提供多企业归属或多角色切换。可选外部部署必须显式开放注册；该开关同时控制普通注册与企业申请。

版本 4 新增申请和申请历史表。已有 schema 3 数据库应先完成备份/副本验证；迁移保留账号、会话、岗位、简历和已有业务数据，日常升级不需要重置账号。
