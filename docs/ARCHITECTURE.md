# 架构与约定

采用分层模块化单体：一个 Python 服务和 SQLite 数据库，企业端与普通端复用原生网页组件，由服务端决定可见和可写范围。

- `domain/`：岗位、规范化、字段条件、核验、重复判断、简历值约束；不依赖 HTTP 或 SQLite。
- `application/`：账号、企业入驻/审核、导入、岗位维护、查询、核验与简历用例，依赖领域和端口。
- `infrastructure/`：SQLite 仓储、迁移、数据来源适配器及 PDF/DOCX 结构校验。
- `web/`：路由、请求边界、Cookie、登录/注册等待和有界 HTTP 连接。
- `bootstrap.py`：选择具体适配器并组装服务；根目录兼容入口保留。

数据 schema 为 4，迁移由初始化器执行，服务启动不自动创建演示账号。v4 新增企业申请与历史表，不重写已有账号、岗位或简历；升级前应备份独立数据库，先验证副本再启动。事务由 unit of work 持有，写操作在事务中重新核对当前权限；HR 撤权无需退出旧会话即可生效。外部解析与纯计算尽量在写事务外执行，写入前复核版本，避免旧页面覆盖新结果。

入驻由 `application/onboarding.py` 编排，`infrastructure/onboarding.py` 负责持久化，`domain/organizations.py` 统一企业名称比较。批准事务内检查管理员、申请人、申请版本和状态、企业名冲突以及个人数据，再建企业、变更角色、保存历史与审计；任一步失败一起回滚。HTTP 层不执行 SQL。完整流程见 [企业入驻](ENTERPRISE_ONBOARDING.md)。

企业负责人和 HR 只能维护自己企业数据；求职者仅见可公开有效岗位及自己的收藏、备注和简历；管理员的公共数据维护权不等于任意企业内部写入权。网页注册由后端固定为求职者，客户端提交角色或企业 ID 不会提升身份。

岗位保留来源、原始记录、变更和人工核验。来源更新与人工下架分别记录，人工核验在原文或规则变化后进入待复核状态。薪资按币种与周期处理，缺失不按零统计；原文未发现要求不能视为“不限”。CSV 导入折叠相同重复行，冲突 ID 退回，企业归属从会话取值。

`GET/POST /api/resume` 和 `GET /api/resume/download` 仅允许当前求职者本人。上传值验证与结构解析后，在事务中再次确认权限并保存，替换成功后返回元数据；失败保留已有文件。PDF/DOCX 上限 2 MiB，PDF 上限 200 页；拒绝加密 PDF、无效结构及危险 DOCX 包结构。pypdf 为固定外部依赖，结构检查不等于病毒扫描。文件不由通用静态路径暴露，下载采用附件响应。

服务仅绑定 loopback，HTTP 连接和读写空闲时间有界；外部 HTTPS 模式通过显式 `--test-origin` 固定可信来源、Host 与安全 Cookie。公网模式另要求 SQLite ≥3.51.3，并拒绝公开演示口令。部署使用自己的身份配置，见 [部署说明](DEPLOYMENT.md)。

测试覆盖当前事务、迁移、权限与 HTTP 边界。私有历史 2.2 checkpoint 不随此版本分发，相应 3 个旧模块对照测试明确跳过，不影响当前 schema 的合成迁移测试执行。
